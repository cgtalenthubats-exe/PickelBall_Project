# Feedback Backlog — จากการพรีเซนต์ลูกค้า

วันที่: 30 กรกฎาคม 2569
สถานะ: **tracking เท่านั้น** — ยังไม่ได้เริ่มทำ รายการนี้จะทยอยเพิ่มเมื่อมี feedback รอบใหม่

รายการด้านล่างคือสิ่งที่ลูกค้าอยากเห็นเพิ่มจากการพรีเซนต์รอบนี้ พร้อมโน้ตทางเทคนิคคร่าวๆ ว่าแต่ละอันตอนนี้ระบบรองรับแค่ไหน และมีจุดไหนต้องตัดสินใจ/ประเมินเพิ่มก่อนเริ่มทำจริง

## 1. รายงานตอนนี้มีแค่รายรับ-รายจ่ายด้านเดียว

**สถานะปัจจุบัน:** หน้า `/admin/reports` มีแต่รายงานฝั่ง**รายรับ** (ค่าจองสนาม + ขายสินค้า, แยกตามเดือน/สาขา/ช่องทาง, ยอดคืนเงิน) — ระบบยังไม่มีแนวคิดเรื่อง "รายจ่าย" เลยแม้แต่น้อย ไม่มีการบันทึกต้นทุน ค่าใช้จ่ายดำเนินงาน หรือค่าใช้จ่ายอื่นๆ ที่ไหนในระบบทั้งสิ้น

**ต้องตัดสินใจ:** ถ้าจะทำรายงานแบบ P&L (กำไร-ขาดทุน) จริงจัง ต้องมีฟีเจอร์บันทึกรายจ่ายใหม่ทั้งหมด (เช่น ค่าเช่า ค่าน้ำค่าไฟ ค่าจ้างพนักงาน ต้นทุนสินค้า) — เป็นงานใหญ่ ควรคุยขอบเขตกับลูกค้าก่อนว่าต้องการระดับละเอียดแค่ไหน

---

## 2. รายงานสต็อก (จำนวนคงเหลือ + มูลค่ารวม)

**สถานะปัจจุบัน:** มีตาราง "ความเคลื่อนไหวสต็อกล่าสุด" ในหน้าสินค้าอยู่แล้ว (รับเข้า/ขายออก/ปรับสต็อก ต่อรายการ) แต่ไม่มีหน้าสรุปภาพรวม "มีของกี่ชิ้น รวมมูลค่าเท่าไหร่" ในรูปแบบรายงาน

**ต้องตัดสินใจ:** ตอนนี้ `products.price` เป็นราคา**ขาย** ไม่ใช่ราคา**ทุน** — ถ้าจะคำนวณ "มูลค่าสต็อกคงเหลือ" มี 2 ทางเลือก:
- ใช้ราคาขาย × จำนวนคงเหลือ (ทำได้ทันที ข้อมูลมีอยู่แล้ว แต่ไม่ใช่มูลค่าทางบัญชีที่แท้จริง)
- เพิ่มฟิลด์ "ราคาทุน" ต่อสินค้า/ต่อล็อตที่รับเข้า แล้วคำนวณมูลค่าจากต้นทุนจริง (ถูกต้องกว่า แต่ต้องเพิ่มข้อมูลใหม่ตอนรับสต็อกทุกครั้ง)

## 3. รายรับแยกตามประเภท (booking / order / rental) ลงรายละเอียดวัน-เวลา

**สถานะปัจจุบัน:** ตอนนี้แยกรายรับได้แค่ "ค่าจองสนาม" กับ "ขายสินค้า POS" เท่านั้น ยังไม่มีหมวด **"rental" (ค่าเช่าอุปกรณ์)** แยกต่างหาก — จริงๆ ตอนนี้ค่าเช่าอุปกรณ์ (ไม้แร็กเกต ฯลฯ) ถูกรวมอยู่ในยอดจองสนามทั้งก้อน ไม่ได้แยกเป็นหมวดของตัวเอง และยังไม่มีรายงานแบบแยกวัน (จ-ศ) หรือแยกรายชั่วโมงเลย

**ต้องประเมินเพิ่ม:** ข้อมูลดิบ (เวลาเริ่ม-จบของการจอง/ออเดอร์) มีพร้อมอยู่แล้วในฐานข้อมูล ทำ report แบบแยกวันในสัปดาห์/แยกช่วงเวลาได้แน่นอนทางเทคนิค แต่ต้องคุยกับลูกค้าเพิ่มว่าอยากเห็นในรูปแบบไหน (ตาราง? heatmap ตามชั่วโมง?) และอยากแยก "rental" ออกจากยอดจองสนามด้วยหรือไม่

## 4. เชื่อมต่อ e-Tax (ใบกำกับภาษีอิเล็กทรอนิกส์ของกรมสรรพากร)

**สถานะ:** ยังไม่ได้เริ่มประเมิน — แผนคือ**ให้ลูกค้าเลือกผู้ให้บริการเอง แล้วเราต่อ API ให้ตามที่เลือก** (รอไว้ก่อน ยังไม่ต้องทำอะไรจนกว่าลูกค้าจะเคาะ)

**ภาพรวมระบบ (สำหรับอธิบายลูกค้า):** e-Tax Invoice ของไทยมี 2 แนวทาง —
- **e-Tax Invoice by Email/Time Stamp** — สำหรับธุรกิจรายได้ไม่เกิน 30 ล้านบาท/ปี ใช้ time stamp ฟรีจาก ETDA ผ่านอีเมล ง่ายแต่ไม่เหมาะกับการยิง API อัตโนมัติจากระบบ
- **e-Tax Invoice & e-Receipt** — สำหรับธุรกิจทุกขนาด ต้องมี digital signature + ใบรับรองอิเล็กทรอนิกส์ (electronic certificate) ส่งผ่าน "ผู้ให้บริการนำส่งข้อมูล" ที่กรมสรรพากรรับรอง — น่าจะเป็นแนวทางที่ตรงกับ Central Group เพราะรายได้เกิน 30 ล้านแน่นอน

**ผู้ให้บริการที่เป็นที่รู้จัก/มีคนใช้เยอะ** (ยืนยันจากการค้นหาล่าสุด แต่ควรเช็ครายชื่อที่กรมสรรพากรรับรองล่าสุดที่ rd.go.th อีกทีก่อนตัดสินใจ เพราะรายชื่อเปลี่ยนได้):
- **INET** (บมจ.อินเทอร์เน็ตประเทศไทย) — เจ้าใหญ่ รายแรกๆ ของตลาด
- **Leceipt** — SaaS เฉพาะทาง e-Tax invoice/receipt ที่ระบบบัญชีอื่นๆ (เช่น PEAK) นิยมต่อผ่าน
- ระบบบัญชีคลาวด์ไทยอย่าง **PEAK** และ **FlowAccount** ก็มีโมดูล e-Tax invoice ในตัว แต่เบื้องหลังเป็นการต่อผ่านผู้ให้บริการอย่าง INET/Leceipt อีกที ไม่ได้ยิงตรงกรมสรรพากรเอง

**ต้องตัดสินใจ:** ลูกค้าเลือกผู้ให้บริการก่อน แล้วเราค่อยดู API doc ของเจ้านั้นมาต่อให้ — งานฝั่งเรารอได้ ไม่ต้องรีบ

## 5. รายงานใบเสร็จ/ใบกำกับภาษีแบบเต็ม + แก้ไขข้อมูลผู้เสียภาษี

**อัปเดต (30 ก.ค.):** คุยกับลูกค้าเพิ่มแล้ว — "แก้ไขได้" ที่ขอ หมายถึงแก้**ข้อมูล template** เช่น ชื่อผู้เสียภาษี/ชื่อผู้จ่ายภาษี ไม่ใช่แก้ตัวเลขยอดเงินในบิลที่ออกไปแล้ว

**ส่วนนี้ทำไว้แล้ว ใช้งานได้จริงตอนนี้:** หน้าใบเสร็จ (`/receipt/[kind]/[id]`) มีฟอร์มให้เจ้าของใบเสร็จ (ลูกค้าที่ล็อกอินอยู่) แก้ไข **ชื่อผู้เสียภาษี / เลขประจำตัวผู้เสียภาษี / ที่อยู่** ของตัวเองได้เลย (`TaxProfileForm` + `updateTaxProfile` action, เก็บที่ `profiles.tax_name/tax_id/tax_address`) แก้เสร็จก็ปริ้นใหม่ได้ทันที

**ที่ยังขาด:**
- **รายงานรวมใบเสร็จทั้งหมด** — ตอนนี้มีแค่หน้าใบเสร็จรายใบ ยังไม่มีตาราง/รายงานรวมทุกใบให้ดูย้อนหลังทีเดียวในหน้าแอดมิน
- **staff แก้ข้อมูลภาษีแทนลูกค้าไม่ได้** — ตอนนี้ฟอร์มแก้ไขจำกัดเฉพาะเจ้าของบัญชีที่ล็อกอินเอง ถ้าเป็นลูกค้า walk-in ที่ไม่ได้ล็อกอิน (พนักงานสร้างออเดอร์ให้) จะยังกรอกข้อมูลภาษีให้ไม่ได้ในตอนนั้น ต้องรอให้ลูกค้าล็อกอินเข้ามาแก้เอง — ถ้าลูกค้าอยากให้ staff กรอกแทนได้ด้วย เป็นงานเพิ่มเติมเล็กน้อย
